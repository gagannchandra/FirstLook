## 2026-11-24 — Setup

- **D1 Python 3.12 (via uv), not system 3.14.** System Python is 3.14; several required libraries (catboost, shap/numba) do not reliably ship 3.14 wheels. The guide says 3.11; 3.12 is the closest version that is well supported.
- **D2 Repo layout.** The guide's `edgetriage/` structure is used at the repo root (`FirstLook/`). The guide pack stays in `guide/` (the guide calls it `docs/`); `docs/` holds generated project docs.
- **D3 Container runtime.** `docker` on this machine is podman's Docker-compatible CLI. `--network none --cpus 2 --memory 2g` work the same way.
- **D4 Dataset source.** Downloaded Zenodo record 1308993 (`admissionprediction-v1.0.zip`, MD5 `73bad18992d2ae4ae86122cd4e8305bd`, verified). The original R scripts were extracted to `data/raw/extracted/` as reference only and were never executed.
- **D5 MLflow dropped.** The guide allows "MLflow (or CSV logs)". CSV/JSON logs in `results/logs/` are used to keep the environment small.

## 2026-11-24 — Phase 1 (data)

- **D6 No patient identifier.** The public file has no patient ID (the original `20_cleanmerged.R` deletes `pat_mrn_id` and `pat_enc_csn_id`; the column `pid` is the CCS code for pelvic inflammatory disease). S1 is therefore a **visit-level** stratified split, as in Hong et al. Repeat patients may appear in train and test, which can inflate S1 scores. This is stated as a limitation; S2 (leave-one-hospital-out) is the stricter estimate.
- **D7 Tier contents.** T1 follows the guide exactly: age, sex, arrival mode, arrival 4-h bin, 7 triage vitals, 200 chief-complaint flags (222 features after one-hot). `arrivalmonth`/`arrivalday` are available at triage but are not in the guide's T1, so they are not used in any tier. T2 = T1 + ESI (223). T3 = T2 + `previousdispo` + all history groups (PMH, historical labs/vitals, prior imaging/EKG, outpatient meds, surgeries, ED visit/admission counts) = 976 features. 5 constant columns are dropped.
- **D8 Site labels.** Sites are anonymised as A/B/C. Volume and admission rate (A: 322k visits, 31.9%; B: 166k, 31.6%; C: 72k, 15.6%) are used to *infer* A = academic trauma centre, B = community, C = free-standing ED. Tables always say "Site A/B/C" and mark the type as inferred.
- **D9 SpO₂ = 100.** The original cleaning removed values `x >= max` with max = 100, so no SpO₂ of 100 exists in the data (max = 99) and many 100s became missing (SpO₂ missing 48%). The feature pipeline maps an entered SpO₂ of 100 to 99, the nearest value the model has seen. Consequence: "not measured" in the training data is a mix of truly missing and SpO₂ = 100; this is stated as a limitation and analysed in E10.
- **D10 ESI encoding.** ESI is one ordinal numeric feature (1–5, NaN if missing), not one-hot. Note: the original script kept the *most recent* ESI when a visit had two; a re-triage could happen after the first assessment. This affects few visits; it is marked "yes (see note)" in the leakage audit.
- **D11 S2 never touches the S1 test set.** Leave-one-hospital-out uses only rows outside the S1 test set: the two source sites are split 80/10/10 into train/val/cal, and the held-out site's remaining rows are the target pool (local-adaptation samples + evaluation). This keeps the S1 test set sealed until Phase 5.
- **D12 S1 proportions.** 80/10/10 train/val/test, then 10% of train is carved out as the S3 calibration set: train 72%, cal 8%, val 10%, test 10% (seed 42, stratified on outcome).
- **D13 Duplicates.** 2 exact duplicate rows are kept: without visit IDs they cannot be told apart from two genuine identical visits, and 2 rows cannot change any result.
- **D14 Temperature unit.** Triage temperature is in °F (valid range 90–110 °F, from the original cleaning script), not °C as the guide's example suggests. The app accepts °F or °C and converts to °F.
- **D15 Chief complaint.** The dataset stores chief complaint as 200 binary `cc_*` flags (including `cc_other`), and a visit can have several (87% have one, 11% two). The app lets the nurse choose up to 3 complaints from a searchable list.
- **D16 Vital ranges in the app.** Valid ranges are the original cleaning limits (e.g. HR 30–299, SpO₂ 60–100, RR 8–69, temperature 90–109.9 °F). Values outside them are rejected with a friendly message instead of being silently set to missing.

## 2026-11-24 — Phase 2/4 engineering

- **D17 Streamlit bound to localhost.** By default Streamlit looks up the machine's public IP over the network at start-up (to print an "External URL"); the app screenshot test caught this as one external connection. `.streamlit/config.toml` now sets `server.address = "localhost"` and `browser.gatherUsageStats = false`. After the change the app process opens no external sockets during the full demo flow, and the browser makes 0 requests to non-local hosts (`scripts/screenshot_app.py` logs them).
- **D18 Pre-declared selection rules (before E2 results were seen).** Best model per tier = lowest validation log-loss after its calibrator; calibrator (Platt vs isotonic, fit on S3) = lowest validation ECE, Platt on ties within 0.001; t_low = largest threshold with NPV ≥ 0.95 on validation; t_high = smallest threshold with PPV ≥ 0.80 on validation.
- **D19 Pre-declared edge-model rule.** For the app, the smallest exported artifact whose validation AUC is within 0.01 of V0 (full selected model) of the same tier.
- **D20 LR export.** skl2onnx mis-sizes `SimpleImputer(add_indicator=True)`, so the logistic-regression pipeline is exported as a hand-built ONNX graph (IsNaN → Where → MatMul → Sigmoid). Every bundle build asserts ONNX-vs-native parity < 1e-4 on all validation rows.
- **D21 Test-set guard in code.** `src/common.py` raises `TestSetSealed` for any request of S1 test rows unless `configs/selection.json` has `date_frozen` set *and* `FIRSTLOOK_OPEN_TEST=1`.
- **D22 Local adaptation uses Platt.** In E6 the local recalibrator is always Platt (2 parameters), because isotonic regression is unstable with 100–500 visits. Because Platt is monotone, Mondrian conformal sets depend only on the order of raw scores within each class, so fitting the calibrator and the conformal thresholds on the same local sample does not bias coverage.
- **D23 T3-lite.** Interpreted as the top-k features (k = 10–50) of the T3 SHAP ranking, which naturally mixes ESI, age, vitals and history fields; the app's history toggle asks only for the history fields that model uses.
- **D24 Tuning time caps.** Optuna studies have a wall-clock cap in addition to the trial budget (T1 ran with caps LR 30 min, RF/XGB/LGBM 60 min, CatBoost 80 min; T2/T3 with LR 20, RF/XGB/LGBM 40, CatBoost 50 min) so that all 15 studies finish on one laptop. The number of completed trials per study is logged in `results/logs/best_*.json` and reported with Table A. Budgets: LR 15, RF 10, XGB 30, LGBM 30, CatBoost 15 trials (guide suggests 30–50; RF/CatBoost/LR get fewer because each trial is slow or the search space is tiny).
- **D25 Safe feature names.** The first T3 run crashed: LightGBM rejects feature names containing JSON special characters, and 55 historical-lab columns contain commas/brackets (e.g. `b-typenatriureticpeptide,pro(probnp)_last`). The shared pipeline now maps them to model-facing names with `[]{}":,` replaced by `_` (no collisions); raw names are still used to read the data and as app form keys. T1/T2/meta files were rebuilt and verified byte-identical (MD5), so T1/T2 models were not retrained; T3 tuning was restarted from scratch.
- **D26 Experiments run sequentially.** With 14 GB RAM, T3 tuning (~8 GB) and E5/E6 cannot run at the same time; E5/E6 was started in parallel once, stopped after 1 minute (no results used), and rerun after T3 finished.
- **D27 T1 compression grid extended to k = all.** No T1 variant with k ≤ 50 came within 0.01 AUC of V0 (best: V1 top-50, 0.842 vs 0.8575): T1's signal is spread over 200 chief-complaint flags. Following the guide's intent (its k list is an example), k = 222 (all T1 features) was added for V1/V2/V3/V4. Even so, no exported variant met the tolerance; by the pre-declared fallback (D19) the highest-AUC export ships: **logistic regression on all 222 features (9.3 KB, val AUC 0.846, ΔAUC 0.011)**. Reported as a narrow miss of the compression criterion, not hidden. The T2 app model uses the same recipe plus ESI. T3-lite met the rule (LightGBM depth 4, 200 trees, top-50 features, 215 KB, ΔAUC 0.0095, 58× smaller).
- **D28 ONNX Runtime telemetry (found by testing).** The app screenshot test showed one external connection from the app process. An OS-level socket watcher plus per-library isolation traced it to **ONNX Runtime 1.32**, which opens HTTPS to `mobile.events.data.microsoft.com` (1DS telemetry, `core/platform/posix/telemetry_1ds.cc`) about 9 s after an inference session is created, on Linux, by default. `onnxruntime.disable_telemetry_events()` does **not** stop it; the environment variable `ORT_DISABLE_TELEMETRY=1` does (verified: 0 connections). It is now set before any ONNX Runtime import (`src/runtime.py`, app, benchmark, compress, final_eval), in the Dockerfile and in `scripts/serve_app.sh`; `tests/test_offline.py` runs the real inference path for 20 s and fails on any non-loopback socket. The earlier host benchmark's byte count was re-measured after the fix. Lesson for the dissertation: "offline" must be verified at the OS level, because dependencies can phone home even when the code makes no network calls. Python audit hooks did not see this (native code).
- **D29 Fixed ONNX converter mismatch is reported, not shipped.** Some converted LightGBM variants differ from native LightGBM by up to 0.07 in probability (missing-value handling in onnxmltools' converter). Every bundle build asserts parity < 1e-4 on all validation rows; the shipped T3-lite model's difference is 3.4e-7, and the T1/T2 LR graphs are exact.

## 2026-11-24 — Phase 5 (final evaluation)

- **D30 Freeze.** All model, calibrator, threshold, conformal and compression choices were frozen in `configs/selection.json` (`date_frozen`), `configs/edge_selection.json` and `docs/frozen_choices.md` (with MD5 hashes of every shipped artifact and the pre-registered success criteria) **before** the test set was opened.
- **D31 S1 test set opened on 2026-11-24**, once, by `src/final_eval.py`, `src/secondary.py --split test` and `src/dashboard_data.py --split test` (run together in one sequence). No choice was changed afterwards.
- **D32 Cut-list items used (guide 06 §6).** (4) 3-seed repeats of the main table were not run; Table A uses 1 training seed with 1,000-resample bootstrap CIs (seed stability is shown for SHAP in E7). E13 usability pilot needs human participants and was not run.
- **D33 L3 PWA scope.** The offline PWA (`app/pwa/`) ports the two logistic-regression bundles (T1, T2) to plain JavaScript (no libraries, no CDN, CSP `connect-src 'self'`); `tests/test_pwa.py` checks probability (<1e-4), band and conformal state against the Python/ONNX runtime on 300 synthetic forms. T3-lite (a LightGBM tree ensemble) is not ported: it would need onnxruntime-web, a multi-MB WASM dependency, and history entry is a desktop workflow. Offline verified with Playwright: service worker installed, context set offline, page reloaded and a prediction made with 0 failed and 0 external requests.
- **D34 Fixes found by end-to-end verification (2026-11-24).** (a) The Docker UI was unreachable at `http://localhost:<port>`: `localhost` resolves to IPv6 `::1` first, podman's pasta forwarder accepts IPv6, but Streamlit listened on IPv4 `0.0.0.0` only. The container now binds `::` (dual-stack); verified on 127.0.0.1, ::1 and localhost. (b) Behind the port-forward the browser's own connection reaches the app from the container's link-local IPv6 address, so the app's "external connections" counter showed 1 in Docker. Verified by listing the container's sockets: every connection was to/from the app's own port 8501 (inbound), none outbound. The counter now counts only outbound connections (not on a port the app listens on); a regression test checks both cases. No outbound traffic was ever present; Docker `--network none` still has only `lo`.
- **D35 Random-patient autofill (2026-11-24).** Both apps have a "Random patient" button with an acuity choice (any / low / medium / high) and an optional missing vital. Values are drawn from hand-set, clinically plausible ranges per acuity (`app/random_patient.py`; the PWA reads the same profiles from `models.json`), never from dataset rows, so the rule "demo patients are synthetic" holds. Each fill shows its seed and is reproducible from it. Tests: every generated form passes validation with no soft-range warnings, and mean predicted risk is ordered low < medium < high (Python T1: 0.02 / 0.35 / 0.92 over 200 seeds each). Frontend redesign follows the dataviz skill: hero number in ink plus a band meter (no gauge/donut), status colours always paired with icon + label, diverging red/blue explanation bars, legend + dodged direct labels on dashboard lines.
